# M3 起手規劃:規則結構化轉錄管線(附件2 → 結構化規則資料集)

> RA 2026-08-04 指示不暫停、續行下一步。本文件為 M3「規則引擎與價格比較」之起手規劃:把 governed 附件2 所載新版 2.6.1–2.6.3 規則條文,經逐字轉錄+保真驗證+INTAKE-APPROVE,產出規則引擎可消費的結構化資料集。規劃本身零規則內容;每一步各有閘門,轉錄完成**不**自動解鎖產品編碼(見 §5)。

## 1. 為何需要轉錄

規則引擎不能直接吃 PDF。目前規則文字唯一合法載體是 `data/governed/nhi-lipid-rules-2026-09-01-r1/attachment-2-rule-revision-table.pdf`(RDL-014);要進 M3,需將其「修正後」欄轉成欄位化資料——轉錄物仍是官方規則內容,因此**同樣走 governed intake 全閘門**,而非直接寫進程式。

## 2. 管線(四單一裁,每步可稽核)

| 步驟 | 性質 | 內容 | 閘門 |
| --- | --- | --- | --- |
| T1 轉錄規格 | 規劃(本件+schema 草案) | 結構化 schema 定稿(§3)、轉錄規則(逐字、NFKC、零詮釋、逐單元錨定+雜湊) | RA PASS 本 PR |
| T2 轉錄執行 | 建置(Codex xhigh) | 腳本讀取 **repo 內 governed 附件2**(雜湊閘門),機械切分右欄條文單元→結構化檔;**轉錄物 payload 置 repo 外**,repo 內僅統計報告(單元數、覆蓋頁次、雜湊) | 派發方雙重覆核 |
| T3 保真驗證 | 建置(Codex xhigh) | 往返驗證:結構化檔重組→正規化文字 vs 附件2 右欄擷取逐位元比對;逐單元錨點覆蓋率;統計式報告 | 派發方雙重覆核 |
| T4 入庫核准 | RA 裁決 | `INTAKE-APPROVE nhi-lipid-rules-structured-2026-09-01-r1 <digest7>` → 新 RDL 條目 → `data/governed/` 入庫+CI 機器驗證 | RA 語式 |

T2/T3 沿用表二程序全部安全慣例:雜湊閘門、強制失敗探針、冪等雙跑、凍結檔驗證、字面稽核、產物安全自我掃描。

## 3. 結構化 schema 草案(欄位名,零內容)

- 資料集:`nhi-lipid-rules-structured-2026-09-01-r1`;格式:JSONL(每行一個條文單元)
- 條文單元欄位:`unit_id`(穩定編號)、`section`(2.6.1/2.6.2/2.6.3)、`table_label`(表一/表二/無)、`clause_path`(層級路徑,如 1.、(1)、①)、`unit_type`(表題/資料列/定義項/條文/註)、`verbatim_text`(逐字轉錄)、`effective_from`(2026-09-01)、`source_anchor`(附件2 頁次+右欄邏輯行區間)、`unit_sha256`
- 表格列另附:`row_index`、`column_labels[]`(表頭逐字)——不拆解語意、不正規化藥名、不推導條件邏輯
- 明確排除欄位:任何 eligibility 判定、任何價格(價格屬第一資料集與附件1 範疇)、任何非逐字之摘要或改寫

## 4. 與既有資產的關係

- **輸入**:governed 附件2(repo 內,clone 即有——不再依賴 session uploads,容器更換免疫)
- **三份候選**(repo 外)退役為 T3 之交叉參考;9/1 生效版確認排程照舊(勘誤攔截,若屆時有勘誤→轉錄資料集依 RDL-013 append-only 出 r2)
- 261 候選「降三酸甘油酯表 0 列」疑點:T2 轉錄會機械揭示新版該表實況(有列就轉出、無列就如實為零),疑點隨轉錄自然結案,無需前置人工認定

## 5. 明確的「還不解鎖」清單

- T4 完成後,結構化規則仍**僅存在於治理儲存**——domain 引擎消費該資料集(真正的規則編碼)需要**另一次 RA 裁決**(範疇語式屆時另擬),且 eligibility 判定依 RDL-002 永久排除
- production 部署、真實價格接線照舊 BLOCKED;v3.2 §32 專業簽核不受本管線影響
