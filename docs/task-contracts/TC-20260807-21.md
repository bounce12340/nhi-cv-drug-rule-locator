## 1. 三個功能

### F1:主檔分頁(藥品查詢)之事實標籤與篩選

- 每張結果卡片加**事實標籤**(依代碼精確比對 RDL-012 生成模組之清單成員資格):`本次公告異動`、`三個月試用清單`、`表二品項`
- 搜尋結果上方加**篩選鈕**:`全部` / 上述三類
- **字眼紅線**:標籤與篩選一律事實陳述;禁止出現給付結論詞彙(以名指涉:eligibility 黑名單)、禁止「符合/不符合××規定」句式

### F3:公告品項分頁之主檔對照(RA 本次指示的核心)

- RDL-012 之 187 筆品項卡片(現僅英文品名+代號)加一個**明確標示來源的對照區塊**:
  `品項主檔對照(健保用藥品項查詢項目檔):中文品名・劑型・現行支付價(含期間)`
- 對照**僅以藥品代號精確比對** `lookupDrugItemMaster`;查無 → 顯示固定文字「品項主檔查無此代號」——**不得模糊比對、不得以英文品名近似補接**
- 兩資料集之值**不得合併為單一欄位**、不得互相覆寫;對照區塊自帶其資料集版本標示

### F4:規則條文 → 章節品項導覽

- 規則逐字查詢結果(2.6.1/2.6.2/2.6.3)加按鈕「查看本章節品項(主檔)」→ 切至主檔分頁並套用**章節篩選**
- 章節篩選=主檔記錄之「給付規定章節」欄**逐 token 精確比對**(該欄為逗號分隔;**嚴禁子字串比對**——`8.2.6.1.` 陷阱同 TC-16,必須有負向測試)

## 2. domain 輔助(允許之最小新增)

- `packages/domain/src/` 允許新增**純函式**顯示輔助:代碼成員資格集(自既有 items 生成模組匯出推得)、依章節 token 列舉主檔品項。零 I/O、deeply-frozen、有測試
- **不改**任何既有查詢函式行為與既有生成模組

## 3. 禁止事項(違反即 BLOCKED)

- 不得修改 `data/governed/**`、`packages/domain/src/generated/**`、`scripts/**`、`apps/api/**`(本單不動 API)
- 既有 257 項測試零修改(TC-20 若先合併則以其後基準為準,派發方於派工時告知)
- 不得出現任何 eligibility 詞彙於引擎自撰文案;價格呈現不得含漲跌/趨勢/優劣語
- 不得執行任何 git 指令

## 4. 驗收標準

1. 五項檢查全綠(測試零修改+新增)
2. F1 標籤與 F4 章節篩選之成員資格/比對有正負向測試(含 `8.2.6.1.` 排除)
3. F3 對照:有對照、查無對照(固定文字)、代碼近似不補接三情境皆有測試
4. bundle 驗證:三標籤字樣在、對照區塊標題在、黑名單詞彙 0 次
5. 自我檢查報告載明:檔案變更、測試數增減、bundle 驗證、五項檢查
