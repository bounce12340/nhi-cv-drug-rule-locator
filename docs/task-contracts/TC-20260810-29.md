# TC-20260810-29:規則逐字查詢——條文所提代碼之主檔藥品辨識區塊

## 0. 問題陳述(派發方已查證)

規則資料集單元 `2.6.1-001` 為約 5,266 字之自由文字,其中嵌有原官方 PDF 之表二藥品表格,但於轉錄時已被**壓平為單欄行序**,且藥品名稱之換行續行落在健保代碼之後:

```
<藥品名稱 前半>
<健保代碼>
<藥品名稱 後半>
```

使用者因此無法辨識條文所列為何藥品。**該資料集雜湊鎖定且經 `INTAKE-APPROVE` 入庫(RDL-015),不得修改。**

派發方實測:2.6.1 條文含 **116 個相異健保代碼**,於藥品主檔 `nhi-drug-items-2026-08-07-r2` 中 **116/116 全部命中**(零查無);2.6.2 含 4 個、2.6.3 含 10 個。詳見 §8。

## 1. 做法:偵測代碼 → 主檔補上辨識資訊

於規則逐字查詢結果中,新增一個**明確標示來源的區塊**,列出該次結果之條文中出現的健保代碼,並以**主檔資料**呈現其藥品辨識資訊。

### 1.1 代碼偵測

- 以**不變量 1 之樣式 `^[A-Z0-9]{10}$`** 之等價字界比對自 `verbatimText` 取出代碼(第二字元允許為數字,如 `A0` 開頭之合法代碼);**不得推測、不得模糊比對、不得自動更正**。**嚴禁自行收窄為僅允許前兩碼為字母之樣式**——派發方曾因此漏檢兩個合法代碼(見 §8)
- 去重並保留條文中之出現順序
- **不得嘗試重組表格結構**——不得由行序推斷「哪個名稱屬於哪個代碼」。此為本單之核心禁令:今日規律一致不代表所有列皆然,一旦推錯即產生「藥名配錯代碼」,於臨床工具屬最嚴重之錯誤類型且無機制可發現

### 1.2 每個代碼顯示之欄位(以 RA「辨識」需求為度)

自主檔取:**中文品名、英文品名、成分、規格量與單位、劑型**。

RA 已明示「我這邊會進行手動確認」,故本區塊之目的是**辨識**而非完整重現:**不納入**價格、價格沿革、給付規定章節、公告異動等欄位——藥品查詢分頁已提供該等資訊。

若某代碼於主檔查無:**顯示固定之查無文字,不得省略該代碼、不得以條文文字填補**。

## 2. 嚴格分區(不得違反)

- 逐字條文**完整保留、逐字不動、不得隱藏或摺疊任何段落**。RA 之「不需要列出表二全部內容」經派發方理解為「不必重組該表格」,**非**「隱藏官方條文」;隱藏官方逐字內容不在本單授權範圍
- 新區塊須自帶**主檔資料集版本識別**與**主檔警語**(`DRUG_ITEM_MASTER_WARNING`,逐字不改),與規則資料集之版本與警語各自標示
- **不得宣稱條文所載藥品名稱與主檔品名為同一值**,不得以主檔品名取代或「更正」條文文字。兩者可能因轉錄時點與來源不同而相異——如實並呈,由使用者自行判讀
- 區塊標題須使使用者明白:此為「條文中出現之代碼在主檔的記錄」,而非條文本身的一部分

## 10. 驗收發現之補正(2026-08-10,派發方)

UI 層交件後,派發方於驗收時實測發現一項呈現瑕疵。**其餘 §5 驗收項全數通過**(乾淨安裝後五項檢查全綠,36 files / 321 tests;§9.1 三檔 SHA-256 與已提交版本逐位元相同;禁止路徑零變更;既有測試零修改)。本節為**本單範圍內之補正**,不另立新單,以維持「單一 head SHA 一次驗收」。

### 10.1 問題

`RuleDrugMasterIdentificationBlock` 於 `RuleLookupResult` 中**無條件渲染**。當 `result.units` 為空陣列時(任何查無之查詢皆會如此——`lookupRuleText` 於日期、版本或查詢無效時一律回傳 `NO_RULE_TEXT_UNITS`),使用者看到:

```
此查詢未取得已驗證的逐字單元。
條文中出現之代碼在藥品主檔的記錄(0 筆)   [展開主檔辨識記錄(0 筆,目前已收合)]
```

在「查無」訊息之下再提供一個可展開、內容為空的控制項,屬無意義之互動負擔。

此非建置者疏失:§4 只要求「預設收合、標題載明筆數」,未規範零筆情形;且既有 TC-24 價格沿革區塊同為無條件渲染(該處 `priceHistory` 實務上不為空,故未暴露此情形)。**規格缺口由派發方承擔。**

### 10.2 應為之行為

依 `units` 與代碼數分三種情形:

| 情形 | 應呈現 |
| --- | --- |
| `units.length === 0`(查無) | **完全不渲染本區塊**。條文都不存在,「條文中出現之代碼」無意義 |
| `units` 非空且代碼數為 0 | **渲染區塊,但不提供展開控制**,顯示固定文案(如「本次結果之條文中未出現符合代碼格式之字串。」);中英雙語 |
| 代碼數 ≥ 1 | 維持現行行為,不得更動 |

第二種情形**不得**改為隱藏。條文存在而未偵測到代碼,與根本沒有條文是不同的事實;明白告知「已檢視、未發現」比默默不顯示更誠實,亦避免使用者誤以為工具未執行辨識。

- 逐字條文之渲染路徑不得因本補正而改變
- 既有 7 項 UI 測試不得為配合本補正而刪改語意;如某項斷言確實與新行為衝突,**停止並回報**,不得自行放寬
