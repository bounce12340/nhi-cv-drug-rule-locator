## 0. 現況與問題

該提示位於 `apps/clinician/App.tsx` 之 UI 字典鍵 `manualReviewDrug`,**非 RA 核定之強制警語**(RA 核定者為 domain 常數 `DRUG_ITEM_MASTER_WARNING`),故文案可調整。

現況以 `styles.review`(琥珀色警告底色 `reviewSurface`/`reviewText`)呈現,顯示條件為 `sectionFilter === undefined && result?.manualReviewRequired`。

實測顯示情境:

| 狀態 | 例 | 現行 |
| --- | --- | --- |
| `EXACT_MATCH` | 代碼精確命中 1 筆 | 已不顯示(旗標為 false) |
| `MULTIPLE_MATCHES` | 成分查詢回 42 筆 | 顯示警告色塊 ← **本單標的** |
| `NOT_IN_VALIDATED_DATASET` | 查無 | 顯示警告色塊 |

問題:多筆結果時,使用者眼前已有 N 張卡片、顯然沒有被自動選取,此時整塊警告色的份量與其資訊量不相稱。

## 1. 多筆結果:改為輕量事實陳述

- 文案改為**簡短事實陳述,並載明實際筆數**,例如「N 筆相符,請自行選擇適用品項與期別。」(實際字句由建置者擬,須符合下列紅線)
- **樣式改為次要文字**(非警告色塊);不得沿用 `styles.review` 之警告底色
- **筆數必須等於畫面實際顯示之筆數**。若套用篩選後顯示數與總數不同,顯示何者須明確且與畫面一致——**不得顯示一個與使用者所見不符的數字**
- 顯示條件簡化:多筆結果即顯示,**不再因套用章節篩選而隱藏**(現行 `sectionFilter === undefined` 之抑制取消)——輕量化後已無干擾疑慮,且篩選後仍是多筆、仍未自動選取

### 1.1 紅線:仍須傳達「系統沒有替你選」

輕量化**不等於刪除**。新文案仍須讓使用者理解:**工具列出全部候選,未代為選取任一品項或期別**。這是 deterministic-lookup 不變量 3 之外顯,不得因美觀而消失。

## 2. 查無資料:維持現狀

`NOT_IN_VALIDATED_DATASET` 之提示**維持現行文案與警告色塊不變**。理由:查無資料時「不自動選取替代品項或替代期別」是使用者**看不到**的事實(畫面上什麼都沒有),需要明確告知;與多筆結果情境性質不同。

## 3. 不得波及

- **`manualReviewRule`(規則逐字查詢分頁之提示)一律不動**——不同分頁、不同訊息,不在 RA 本次裁示範圍
- `styles.review` 仍由 §2 與 `manualReviewRule` 使用,**其定義不得更動**;輕量樣式須為新增樣式
- **引擎零變更**:`packages/domain` 不得修改;`manualReviewRequired` 之計算與 API 回應**維持原樣**(仍為 `status !== "EXACT_MATCH"`)。本單只改畫面如何呈現該旗標,不改旗標本身
