## 0. 問題陳述(RA 實例,已由派發方複現)

代碼 `AC47928100`(律脂 膜衣錠20毫克)以 `as_of_date=2026-09-02` 查詢:

- 主檔回傳 `2.93`(期間 `1130401`→`9991231`)——**此為正確之 fail-closed 行為**:主檔資料集係 2026-08-06 之快照,不含 2026-09-01 公告,引擎依不變量 3 不得推算或替換未來價
- 公告資料集另載 原支付價 `2.93` → 初核價格 `2.78`,生效 `115/9/1`,章節 `2.6.1`

**兩者皆正確,缺的是畫面沒說明這件事**。使用者因而誤認工具給了過時價格。本單修正呈現,不修正引擎。

## 1. 新舊價格對照(置於卡片顯著位置)

代碼屬公告異動集合時,於結果卡片**顯著位置**(主檔詳細欄位之前)呈現對照:

- 版面:`原支付價 {priceBefore} → 初核價格 {priceAfter}`,並列生效日與給付規定章節,四個值**全部逐字取自公告資料集**
- **關鍵治理界線**:此對照之兩個價格值**同屬公告資料集之欄位**(`priceBefore` / `priceAfter`),因此**不構成跨資料集合併**。**嚴禁**將主檔之 `applicablePricePeriod.paymentPriceRaw` 與公告之 `priceAfter` 配對成對照——即使兩者數值相同亦不得如此,該行為即違反 RDL-019/021 之嚴格分區
- 對照區塊須標示其資料集版本與公告警語(沿用現有 `ITEM_WARNING`,逐字不改)
- 代碼**不屬**公告異動集合時:**不顯示對照區塊**,亦不得以主檔值虛構任何「新價」

## 2. 主檔快照時點提示(修正 RA 所遇之誤解)

主檔區塊於**同時滿足**下列兩條件時,顯示一則事實提示:

1. 查詢之 `as_of_date` **不早於**公告生效日(`2026-09-01`),且
2. 該代碼屬公告異動集合

提示內容須為**純事實陳述**,載明:主檔資料集版本與其為特定時點之快照、其最新價格期間之起迄、以及本次公告另載有該日之後之異動(指向 §1 對照區塊)。

**紅線**:

- 不得宣稱任一價格為「正確」「現行」「應適用」之價格
- 不得代為推算、替換、合併任何價格值
- 不得出現 eligibility 黑名單詞彙(中英雙語皆適用)
- 主檔之 `applicablePricePeriod` 顯示值**不因本提示而改變**

## 3. 價格沿革收合

- `價格沿革` / `Price history` 區塊**預設收合**,提供可點擊之展開/收合控制
- 控制項須有明確可讀標籤(中英各一),並標示目前狀態與筆數;鍵盤可操作、具無障礙標記(`accessibilityRole` / `accessibilityState`)
- 展開後之內容與現行**完全相同**(逐字值、期間、排序皆不變)
- 收合狀態為每張卡片獨立;**不持久化**(不寫入 localStorage,避免與 TC-22 之偏好儲存混淆)
- **主檔之目前適用期間價格不屬沿革,不得一併收合**——該值須始終可見

## 4. 成分查詢之可讀性

成分查詢已可運作(如 `SIMVASTATIN 20 MG` 回傳 `MULTIPLE_MATCHES` 42 筆),本單不改查詢語意。僅要求:多筆結果下 §1 對照與 §3 收合行為逐卡一致,且卡片不因新增區塊而在手機版面溢出(沿用 TC-21 §1.5 之 768px 斷點決策純函式)。

`paymentPriceRaw` 為 `0.00` 等值一律**逐字顯示**,不得隱藏、不得補值、不得推論其意義。
