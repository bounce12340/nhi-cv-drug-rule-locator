## 2. 部署守門診斷強化

`.github/workflows/deploy.yml` 之 `Require deploy secrets` 步驟現況:兩個 secret 任一為空即輸出**同一則**訊息,無法區分成因。已實測發生之三種成因:

1. 兩者皆空——未設定,或設在 Environment / Dependabot 範圍(該範圍 secret 不進入本工作流)
2. 單一為空——名稱拼錯或大小寫不符
3. 值夾帶空白——貼上時多帶換行,wrangler 收到 `"***\n***"` 而報 `Invalid account ID`

改為逐項辨識並給出可執行指引。**紅線**:

- **絕不列印任何 secret 值、長度、前後綴或任何可回推之特徵**;只報告「哪一個」與「何種型態問題」
- 不得將 secret 值寫入 `GITHUB_ENV`、輸出檔或 artifact(遮罩僅對原字串生效,經修剪之變體可能不被遮罩)
- 不得放寬守門:任一條件不滿足即 `exit 1`,不得降級為警告後續跑
- 其餘步驟(checkout/setup/install/export/deploy/smoke)**一律不動**
