## 2. 紅線:規則資料集之版本與警語永遠可見

`result.datasetVersion`、`RULE_TEXT_WARNING`、`sourceTag`,以及 `manualReviewRule` 提示,**一律不得被收進任何摺疊控制之內**,必須在使用者未展開任何區塊時即可見。

理由:主檔辨識區塊自帶主檔警語,若規則資料集警語被摺疊,使用者可能展開主檔、讀完 116 筆藥品資訊,卻從未看見「本工具非健保署系統⋯⋯實際規定以健保署公告為準」。跨資料集嚴格分區之意義即在於每個資料集都自己講清楚自己是什麼,摺疊不得使其中一方消音。

## 3. 官方條文樹狀結構

### 3.1 結構

兩層:

- **第一層:章節**(`section`,如 2.6.1)。查詢回傳跨章節時各自為一節點;僅一章節時仍須顯示該層,不得省略
- **第二層:單元**(`unitId`,如 2.6.1-001 至 2.6.1-043)。每個單元獨立展開

實測單元數:2.6.1 = 43、2.6.2 = 8、2.6.3 = 16。

### 3.2 節點標題只准放結構性中繼資料

單元節點之標題**僅得**顯示:`unitId`、`unitType`(條文/表題/資料列/註/定義項)、`tableLabel`(無/表一/表二)、`clausePath`(非空時)。得另加字元數等純計量資訊。

**嚴禁於收合狀態顯示逐字內容之任何節錄、摘要、開頭數字、預覽片段。** 節錄官方條文即為部分引用,可能使讀者對條文內容形成錯誤印象,且截斷點由工具決定而非官方。此為本單新增之紅線,與 TC-29 §1.1「不得重組表格」同性質:寧可不顯示,不可顯示可能誤導者。

### 3.3 展開後

顯示該單元完整 `verbatimText`,**位元組一致**,不截斷、不加省略號、不改行、不做任何字元正規化。

### 3.4 全展開／全收合

單元數達 43,逐一點擊不可行。章節層須提供**全部展開／全部收合**控制,雙語、具無障礙標記。

## 4. 保留不動
