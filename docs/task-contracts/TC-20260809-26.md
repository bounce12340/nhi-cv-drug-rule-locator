## 0. 問題陳述

B 軌五份委任包撰於產品**上線前**。派發方複查發現至少 `B1` 之「產品事實」與現況不符,而 **B1 是要交付外部律師作為意見書事實基礎的文件**——事實錯誤會使意見基於錯誤前提,不僅無用且可能誤導後續決策。

**本單目的:使每一份委任包所述之產品事實與現況一致,讓外部專業對「真正存在的產品」出具意見。**

## 1. 全面事實稽核(五份皆須逐句核對)

逐句核對 `docs/b-track/B1`–`B5` 中**所有關於產品現況之陳述**,對照下列權威來源:`docs/regulatory-decision-log.md`(尤其 RDL-018 至 RDL-023)、`CHANGELOG.md`、`docs/launch-runbook.md`、`docs/source-register/drug-item-master.registry.json`、`apps/clinician/App.tsx`。

- 陳述**過時**→ 依實際狀況改寫
- 陳述**仍然正確**→ **不得為求一致而改動**;於報告中列出「經核對仍正確」之項目與其依據
- **不得臆測**:任何無法從上述來源佐證之事實,**停止並回報**,不得填補

派發方複查已知之兩處(供起點,**不代表僅此兩處**):

1. **B1 §1 末句**「目前狀態:demo 階段,未上線、未送審;價格顯示僅虛構示範資料」——三項皆已不成立
2. **B4 §2 W1 表前敘述**提及之承載畫面與現行 UI 不符(示範分頁已於 G1 整併移除,現為兩個查詢分頁)

## 2. B1 產品事實應涵蓋之現況要點

改寫後之 B1 §1 須據實載明(以下為**應涵蓋之事實類別**,實際數值與版本號由建置者自權威來源取得,不得抄本契約):

- **已上線**:上線日期與治理依據(RDL-018)、對外主機名、公開可用、無帳號、不蒐集任何個人資料、不處理病人資料
- **介面**:現行查詢分頁組成
- **資料性質**:官方公告與官方項目檔之**逐字轉錄**,列出現行三個已入庫資料集之版本識別;經雜湊保真鏈與 RA 逐字核准入庫
- **價格顯示為真實資料**:公告之原支付價與初核價格、主檔之支付價與價格沿革;as-of-date 為區間比對且無最近期回退
- **永久排除項不變**:診斷、治療建議、劑量計算、病人資格判定(RDL-002)、任何病人資料處理
- **強制警語**:結果與介面所載之警語性質(不可作為申報依據等)
- **尚未發生者**:商店送審、原生 App 發行、帳號功能

### 2.1 必須據實揭露之治理事實(不得省略)

RDL-018 記載:本次 production 發布**未取得 v3.2 §32 之法律/個資/資安專業簽核**,係 RA 明示承擔風險之**誠實偏離登記**(非合規宣告)。

**此事實必須寫入 B1**——律師對「尚未上線的規劃中產品」與「已在營運中且未經法律審查的產品」之風險評估與建議急迫性不同。隱去此節將使意見失真。以中性事實陳述書寫,不作自我辯解、亦不誇大。

### 2.2 B1 §2 委任問題增列一題

現況既已上線,增列一題請律師回答:**若定性為醫療器材軟體,對一個「已在營運中」之系統,其立即義務、風險與建議處置順序為何**(含是否須暫停服務、補正時程、主管機關溝通方式)。原有四題保留不動。
