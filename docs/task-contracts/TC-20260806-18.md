# TC-20260806-18:藥品品項主檔每月自動更新管線

- 派發方:Claude Fable 5(dispatcher/acceptor)
- 建置者:Codex GPT-5.6 Sol,reasoning effort **xhigh**(RDL-010)
- 派工日:2026-08-06
- 治理依據:RA 2026-08-06「D3可以執行每個月自動更新」
- **核心邊界**:管線**只偵測、只推導、只報告、只開單**。它**永遠不寫 `data/governed/`、永遠不自動核准、永遠不自動合併**——入庫仍須 RA 逐字 `INTAKE-APPROVE`。版本 append-only(RDL-013),舊版永久保留以支援 as-of-date 回溯。

## 1. 背景

來源(政府資料開放平臺 23715「健保用藥品項查詢項目檔」)**每月更新**。現行入庫版本為 `nhi-drug-items-2026-08-06-r1`(RDL-020)。管線須偵測上游變動並把差異攤在 RA 面前,讓核准成為一個「看差異、簽語式」的動作。

## 2. 範圍(四項)

### 2.1 參數化 `scripts/drug-item-subset-derive.mjs`

現行三個常數寫死:來源路徑、`EXPECTED_SOURCE_SHA256`、`EXPECTED_SOURCE_DATA_ROWS`。

- 新增選用旗標:`--source <path>`、`--expect-sha256 <hex>`、`--expect-rows <n>`、`--out <path>`
- **向後相容為硬性要求**:未帶旗標時行為與現行**完全相同**(相同預設路徑、相同常數、相同輸出),**既有 8 項測試一字不改且全數通過**
- **雜湊閘門語意不變**:仍為 fail closed;旗標只是改變「被比對的預期值」,**不得新增任何略過閘門的路徑**
- 欄名與欄序檢查維持不變(新版本若改欄位結構,應 fail closed 並由人判讀)

### 2.2 機器可讀來源登錄 `docs/source-register/drug-item-master.registry.json`

管線之權威狀態檔(人類敘述仍在同目錄 `.md`,並指向本檔):

```
{ "schema": "source-registry/v1",
  "endpoint": "<23715 之 resource 端點>",
  "datasetPlatformId": "23715",
  "license": "政府資料開放授權條款-第1版",
  "current": { "datasetVersion": "...", "sourceSha256": "...", "sourceBytes": n,
               "sourceDataRows": n, "subsetSha256": "...", "subsetRows": n,
               "datasetDigest": "...", "fetchedAt": "YYYY-MM-DD" } }
```

初始內容以現行 RDL-020 之實際值填入。

### 2.3 檢查腳本 `scripts/drug-item-refresh-check.mjs`

1. 依 registry 之 `endpoint` 取得上游檔案至暫存路徑(**不得寫入 repo 追蹤路徑**)
2. 計算 SHA-256、位元組數、資料列數
3. **與 `current.sourceSha256` 相同** → 輸出 `{"changed": false, …}`、exit 0、**不產生任何檔案或 PR**
4. **不同** → 以 §2.1 之旗標推導新子集(預期值取自本次實測),並產生:
   - 新子集檔至暫存路徑 + 其 SHA-256、列數、相異品項數
   - **新 dataset digest**(依 `packages/source-intake/src/storage.ts` 之 `computeDatasetDigest` 規則,不得自行另立演算法)
   - **差異統計**(對照現行 governed 子集):新增品項數、移除品項數、價格期別新增數、章節歸屬變動品項數、欄位結構是否相同
5. 取得失敗、雜湊/結構閘門不過、上游回非 200 → **非零碼結束並明確報錯**,不得產生半成品

### 2.4 排程工作流 `.github/workflows/drug-item-refresh.yml`

- 觸發:`schedule`(每月一次)+ `workflow_dispatch`(手動)
- 權限最小化:`contents: write`、`pull-requests: write`,其餘 `none`
- 步驟:跑 §2.3 →
  - **無變動**:於 job summary 記一行,結束(**不開 PR、不發通知**)
  - **有變動**:
    1. 新子集以 **GitHub Actions artifact** 上傳(**不入 repo**),保留期 90 天
    2. 更新 `registry.json` 之 `pending` 區段(不動 `current`)與人類 `.md` 追記
    3. 產生 `docs/stage3/drug-item-refresh-<YYYY-MM-DD>.md` 差異報告(**僅計數,不得含代碼/品名/價格**)
    4. 開 **draft PR**,標題標明偵測到新版本;PR 內文須包含**供 RA 逐字複製的核准語式**:`INTAKE-APPROVE nhi-drug-items-<YYYY-MM-DD>-r1 <digest7>`
- **嚴禁**:自動合併、自動核准、寫入 `data/governed/`、將子集內容寫進 repo 或 PR 內文

## 3. 禁止事項(違反即 BLOCKED)

- 不得寫入 `data/governed/` 任何位元組
- 不得於 repo 追蹤路徑或 PR 內文出現任何藥品代號、品名、價格
- 不得修改既有 248 項測試、既有生成模組
- 不得新增任何略過雜湊/結構閘門之路徑
- **不得執行任何 git 指令**(掃描由派發方於提交後執行)

## 4. 驗收標準

1. 五項檢查全綠:typecheck / test(248 + 新增)/ export:web / worker:types / worker:dry-run
2. **向後相容證明**:不帶旗標之推導輸出與現行 governed 子集逐位元組相同(`e4783015…`);既有 8 項測試零修改通過
3. 帶旗標路徑有測試:自訂來源/預期值/輸出路徑可運作,且雜湊不符仍 fail closed
4. §2.3 之「無變動」路徑以合成 fixture 測試:回 `changed:false` 且零檔案產生
5. §2.3 之「有變動」路徑以合成 fixture 測試:差異統計正確、digest 與 storage.ts 規則一致
6. 差異報告經檢查無代碼/品名/價格
7. workflow YAML 通過語法檢查;權限最小化可驗
8. 自我檢查報告載明:檔案變更、測試數增減、向後相容證明、各探針結果

## 5. 中斷韌性

先寫產物、後寫報告;產物 write-once。中斷時已寫產物即為交付狀態。

## 6. 非目標

- 不做自動入庫、不做自動核准、不碰引擎/UI
- 不處理上游欄位結構變更之自動適配(應 fail closed 交人判讀)
