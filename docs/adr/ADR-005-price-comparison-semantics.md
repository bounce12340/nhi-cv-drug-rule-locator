# ADR-005: 價格比較語意(§30 #11)

- Status: **ACCEPTED**(語意規則定案;比較群組之逐組核定流程由 RA/藥事人員於資料到位後執行)
- 依據:v3.2 §6、§7.5、§11.3–§11.4、§20.8

## Context

價格比較是誤導風險最高的功能:單位不可比、資料缺漏、或把健保支付價誤當自付額,都可能影響處方行為。語意必須先於實作定案。

## Decision

1. **名稱紅線**:一律稱「健保支付價」;不得表述為病人自付金額、採購成本、零售價、廠商報價或核付保證(§11.4)。
2. **可比性以 `comparability_key` 決定**,至少含:有效成分組成、含量(或核准之等效基準)、劑型、給藥途徑、釋放型態、複方比例、支付單位、規格量(§7.5)。**全部相容才可 `DIRECTLY_COMPARABLE`**;規格不同僅 `CONTEXT_ONLY`;其餘 `NOT_COMPARABLE`/`INSUFFICIENT_DATA`。
3. **價格狀態閘門**:每筆回傳 `price_status = CURRENT|FUTURE|MISSING|STALE|CONFLICT`;**任一候選非 CURRENT 即不得做最低價排序**,只能顯示資料狀態(§11.3)。缺漏不得顯示 0、不得沿用未確認舊價、不得以相鄰產品/平均值/模型推測補值(§6)。
4. **禁用語**:「推薦」「最佳」「首選」「最省」及節省百分比(不可比時);不自動計算每日/療程費用,除非劑量來源正式、換算經 RA/藥事核准、假設明示且不作處方建議(§11.4)。
5. **互動上限**:單次比較至多 4 項(§11.3);手機禁用水平捲動大表格,現行/未來價分開顯示並附生效日(§20.8)。
6. **Production gate**(§6,逐項機器檢核後才可啟用比較功能):全候選 VERIFIED 有效價、單位與規格量已正規化、比較群組經核定、無重疊價格版本、來源未逾更新期限、缺漏/過期/衝突不參與排序。
7. `ingredient_category` 僅輔助搜尋/顯示/品質檢查,不得單獨作為給付規則判定依據(§7.2)。

## Consequences

- API 契約(tracker #33)之 compare 端點欄位以本 ADR 為準。
- 比較群組核定屬 governed 程序:群組建立=Maker、核定=RA/藥事 Checker,紀錄可稽核。【待人工確認:核定工作流與人選,價格主檔到位前】
- 價格主檔缺口警示:現有 57 筆僅為異動清單,啟用比較前必須另行取得完整現行支付價主檔並走 governed intake(§6)。
