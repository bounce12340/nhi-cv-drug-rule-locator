# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Demo-only foundation (Phase 0 + Phase 0.5) of a Taiwan NHI cardiovascular / lipid-lowering drug lookup tool for clinicians. One deterministic lookup core serves both an Expo app (Web/iOS/Android) and a Cloudflare Worker API. All drug records are invented `DEMO_DATA_ONLY` data; the project is deliberately blocked from containing real NHI rules, payment prices, patient data, or eligibility decisions (see "Governance and data boundaries").

## Commands

pnpm monorepo (`apps/*`, `packages/*`), Node >= 22, pnpm 10.30.1, ESM throughout.

```bash
pnpm install
pnpm typecheck        # all packages; the API package first regenerates worker-configuration.d.ts via wrangler
pnpm test             # vitest run; root vitest.config.ts picks up packages/**/src and apps/**/src *.test.ts
pnpm test:watch
pnpm exec vitest run packages/domain/src/index.test.ts -t "part of test name"   # single file / single test
pnpm export:web       # Expo static web export → apps/clinician/dist
pnpm worker:types     # wrangler types --check: fails if generated Worker types drifted
pnpm worker:dry-run   # wrangler deploy --dry-run: validates Worker config; never deploys
pnpm --filter @nhi-cv/clinician start:web   # local dev server
```

There is no lint script; `pnpm typecheck` is the static gate. CI (`.github/workflows/ci.yml`) runs exactly: typecheck, test, export:web, worker:types, worker:dry-run. CONTRIBUTING.md requires running all five locally before pushing.

iOS/Android simulator or device runs are BLOCKED in this environment (no full Xcode, no `adb`); do not claim native runtime verification.

## Architecture

There is no build step anywhere: workspace packages export TypeScript source directly (`"exports": { ".": "./src/index.ts" }`, `noEmit`, moduleResolution Bundler). Consumers import source; do not add `dist/` imports or a compile pipeline.

- `packages/domain` (`@nhi-cv/domain`) — the single lookup decision point. Pure functions, immutable invented records, no I/O, no network, no patient state. Both the app and the API call it, which is how Web/iOS/Android and the API stay behaviorally identical. Exports `lookupMedication`, `getDatasetMeta`, the normalization helpers, and the demo dataset constants (version, finite coverage window 2026-08-01 → 2026-08-31, mandatory warning strings).
- `packages/contracts` (`@nhi-cv/contracts`) — transport validation for the API. `parseLookupRequest` allowlists exactly `query` / `as_of_date` / `dataset_version` and rejects any unknown field (this is the patient-data firewall), plus the JSON error contract.
- `apps/api` (`@nhi-cv/api`) — Cloudflare Worker exposing only `GET /health`, `GET /v1/meta`, `POST /v1/lookup`; everything is handled inside the fetch handler with no global mutable request state. Structured logs carry event, status, candidate count, and request ID — never query content. `apps/api/worker-configuration.d.ts` is generated by `wrangler types`, is gitignored, and must never be hand-written; the `Env` type comes from it.
- `apps/clinician` (`@nhi-cv/clinician`) — Expo SDK 57, a single search-first screen (search field autofocused) that calls `@nhi-cv/domain` directly. Mandatory demo warning and no-patient-data notice are part of the screen.
- `packages/source-intake` (`@nhi-cv/source-intake`) — Node-only Phase 0.5 quarantine gate for `SYNTHETIC_TEST_ONLY` material: fixed manifest schema, SHA-256 over raw bytes, `synthetic://` provenance, an explicitly injected authority registry (the default registry is empty), and an RA-evidence state machine. Every outcome — including `VERIFIED` — is `QUARANTINED` with `publishable` / `payloadReleased` / `downstreamUseAllowed` always `false`. It is intentionally not wired to domain/API/UI; do not connect it downstream and do not make it accept official data.

## Deterministic-lookup invariants (docs/architecture.md — do not weaken)

1. Codes: NFKC → trim → uppercase → strip spaces/hyphens, then surface-check `^[A-Z0-9]{10}$`; exact match only. A near-miss (one character off) must return `NOT_IN_VALIDATED_DATASET` — never an auto-corrected or suggested code.
2. Names: normalize character form, case, and repeated whitespace only — never strip strength or dosage form. Multiple hits return `MULTIPLE_MATCHES` with all candidates; never auto-select one.
3. Fail closed: invalid `as_of_date`, a date outside the dataset coverage window, or a `dataset_version` other than the loaded one returns `NOT_IN_VALIDATED_DATASET`; never substitute the latest data.
4. Every non-`EXACT_MATCH` result sets `manualReviewRequired: true`. `EXACT_MATCH` only means the record exists in the dataset — it never implies coverage or patient eligibility.
5. Changes to deterministic behavior require accompanying negative tests (no auto-correct, no auto-select, fail closed). docs/test-matrix.md is the assertion inventory and should stay in sync.

## Governance and data boundaries

Read `docs/spec-source-status.md` and `docs/regulatory-decision-log.md` before substantive changes; `docs/phase-plan.md` defines what is BLOCKED.

- All drug/price/rule examples must be visibly invented, marked `DEMO_DATA_ONLY`, and carry the warning `示範資料，非健保署核定資料／不可作為申報依據。` in UI, API, and results.
- BLOCKED until the Phase 1+ gates are approved: importing official NHI rules or real payment prices, production deployment, and any "符合／不符合給付" (eligibility) logic or copy. This applies even to official-looking data supplied mid-session (announcements, CSVs, spec excerpts): such material may enter only through the governed source-intake process with provenance and RA approval — never by direct commit, memory, or web search (RDL-005; only a designated regulatory authority can unblock).
- No patient data in any form — no patient, diagnosis, or lab fields in code, contracts, logs, tests, or docs.
- Merge governance (CONTRIBUTING.md): Claude Fable 5 dispatches work, sets the acceptance criteria at dispatch time, and performs the independent acceptance; Codex GPT-5.6 Sol (xhigh reasoning) does the implementation within the dispatched scope. The builder never self-approves, and the acceptor must not be the builder of the head SHA under review — a SHA built by Fable 5 itself needs the user or another designated independent acceptor. Merging to `main` requires that acceptance of the exact head commit SHA plus all five CI checks green for that SHA; any new commit, amend, or rebase invalidates prior acceptance. PRs must fill in the safety checklist and SHA gate from `.github/PULL_REQUEST_TEMPLATE.md`.
